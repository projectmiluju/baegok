## 1. 프로젝트 개요

### 배경과 목적

IT 교육생들은 매일 코딩을 하지만 대부분 학습 기록을 남기지 않습니다. 교육이 끝나면 "내가 뭘 했는지" 정리하는 데 시간을 써야 하고, 교강사도 수강생의 학습 상황을 대화 없이는 파악하기 어렵습니다.

**배곡**은 이 문제를 해결합니다:

- **수강생에게:** GitHub push만 하면 AI가 자동으로 학습 내용을 분석·요약·기록
- **교강사에게:** 수강생의 학습 현황을 대화 없이도 파악 가능
- **IDE에서:** MCP(Model Context Protocol)로 Cursor/Claude Code 등에서 직접 학습 데이터 조회

### 핵심 워크플로우

```
수강생이 평소처럼 코딩하고 push
  → 배곡이 자동으로 커밋 분석 (Claude API)
  → 일일 학습 요약 생성
  → 원할 때 기간별 리포트/학습 로드맵 조회
  → IDE에서 MCP로 학습 데이터 직접 조회
```

## 2. AI 활용 전략

### 2-1. miluju-studio: AI 에이전트 워크플로우 OS

이 프로젝트는 **miluju-studio**라는 AI 에이전트 워크플로우 시스템을 사용하여 개발했습니다. 1인 개발자가 AI 에이전트와 체계적으로 협업할 수 있도록 설계된 스킬 기반 파이프라인입니다.

```
/spec → /ui → /build → /qa → /ship → /docs
```

| 스킬     | 역할            | AI가 수행한 작업                            |
| -------- | --------------- | ------------------------------------------- |
| `/spec`  | 프로덕트 오너   | PRD 작성, 예외 처리 정책, GitHub Issue 분해 |
| `/ui`    | UI/UX 디자이너  | 디자인 시스템 정의, 컴포넌트 명세서, 한글화 |
| `/build` | 풀스택 엔지니어 | 코드 구현, 타입 안전성, 안티패턴 방지       |
| `/qa`    | QA 엔지니어     | 테스트 코드 작성, PR 리뷰, 버그 리포트      |
| `/ship`  | 릴리즈 매니저   | 커밋 분리, 메시지 한글화, PR 생성           |
| `/docs`  | 기록관          | 개발 일지, ADR, STATUS 갱신                 |

각 스킬은 명확한 입력/출력 규약과 HARD GATE(진행 조건)를 갖고 있어, AI가 단계를 건너뛰거나 불완전한 산출물을 넘기지 않도록 합니다.

### 2-2. 안티-아첨 프레임워크

AI 에이전트의 가장 큰 위험은 "아첨"입니다. 사용자의 아이디어에 무조건 동의하면 품질이 떨어집니다. miluju-studio는 다음 규칙을 강제합니다:

- 모든 답변에 **입장(Stance)을 취할 것** — 중립은 무책임
- 칭찬 전에 **가장 약한 고리를 먼저 지적할 것**
- "좋은 아이디어네요" 대신 **구체적 근거나 약점을 지적할 것**

이 원칙 덕분에 QA 단계에서 PR 리뷰의 P0 버그를 놓치지 않았고, 실제 배포에서 발생할 수 있는 문제를 사전에 차단할 수 있었습니다.

### 2-3. 1인 개발자 5원칙

| 원칙                    | 적용                                           |
| ----------------------- | ---------------------------------------------- |
| "나중에"는 거짓말이다   | 모든 이슈에서 테스트·문서화를 즉시 수행        |
| 시간은 유한하다         | MVP 스코프를 칼같이 구분 (Out of Scope 명확화) |
| "다 할 수 있다"는 함정  | AI에 위임할 것과 직접 할 것 구분               |
| 기록하지 않으면 없는 것 | ADR 11건, Dev Log 4건, STATUS.md 실시간 갱신   |
| 완벽보다 일관성         | 모든 이슈에 동일한 워크플로우 적용             |

## 3. 사용한 AI 도구

### 3-1. Claude Code (Anthropic)

**주 개발 도구.** 코드 구현, 테스트, PR 리뷰, 문서 작성의 모든 단계에서 사용.

- **프롬프트 전략:** miluju-studio 스킬을 슬래시 명령(`/build`, `/qa`, `/ship` 등)으로 호출하여 역할별 맥락을 주입
- **컨텍스트 관리:** 대화가 길어지면 자동 요약하여 지속적 맥락 유지
- **코드 생성:** TypeScript(Hono, Next.js), Python(FastAPI), SQL(Prisma), Docker, Nginx 등 전 스택

### 3-2. GitHub Copilot (PR 리뷰)

- PR 생성 시 **자동 코드 리뷰** 실행
- #11 PR에서 API 응답 엔벨로프 미언랩 P0 5건 발견 → 배포 전 수정
- #12 PR에서 Dockerfile 패키지 매니저 혼재, frozen-lockfile 실패 등 P0 2건 + P1 3건 발견

### 3-3. Claude API (서비스 내 AI)

배곡 서비스 자체에서 Claude API를 활용:

- **커밋 분석:** GitHub diff를 Claude에 전달하여 학습 내용 요약 + 기술 태그 추출
- **일일 학습 요약:** 하루의 모든 커밋 분석을 통합하여 한국어 학습 요약 생성
- **기간 리포트:** 강점/약점/통계 분석 + 학습 로드맵 생성

## 5. AI와의 협업에서 배운 것

### 5-1. AI는 "도구"가 아니라 "동료"로 써야 한다

단순히 "코드 생성기"로 쓰면 품질이 낮아집니다. 역할을 분리하고(spec/build/qa/ship), 각 역할에 맞는 원칙과 제약을 부여해야 AI가 일관된 품질의 산출물을 만듭니다.

### 5-2. PR 리뷰는 AI에게 맡겨라

GitHub Copilot PR 리뷰가 사람보다 더 꼼꼼하게 API 응답 구조 불일치, Dockerfile 설정 오류, 보안 취약점을 잡아냈습니다. #11에서 P0 5건, #12에서 P0 2건 + P1 3건을 배포 전에 발견했습니다.

### 5-3. 반복되는 실수를 기록하라

이 프로젝트에서 "API 응답 엔벨로프 미언랩"은 3번 반복된 패턴이었습니다 (#10 프론트엔드 15건, #11 MCP 5건, #11 roadmap snake_case). Dev Log에 기록해두면 같은 실수를 줄일 수 있습니다.

### 5-4. 마감은 스코프를 정리하게 만든다

7일이라는 제약 덕분에 "반드시 할 것"과 "안 할 것"을 명확히 구분했습니다. K8s 대신 Docker Compose, RDS 대신 Docker 내 PostgreSQL — 모두 "지금 필요한 최소한"을 선택한 결과입니다.

## 6. 결론

배곡은 AI를 두 가지 차원에서 활용합니다:

1. **서비스 내 AI:** Claude API로 학습 커밋을 자동 분석하여 교육생과 교강사에게 가치 제공
2. **개발 과정의 AI:** miluju-studio 워크플로우로 1인 개발자가 7일 만에 풀스택 MVP를 완성

7일 동안 12개 이슈, 19개 PR, 95+ 테스트, 10개 Docker 컨테이너로 구성된 서비스를 배포까지 완료했습니다. 이는 AI와의 체계적 협업 없이는 불가능한 성과입니다.

**배곡은 "AI가 교육을 어떻게 바꿀 수 있는가"에 대한 실제 작동하는 답입니다.**
